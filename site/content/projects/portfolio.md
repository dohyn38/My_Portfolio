## 1 활동 개요

수행 시기 : 2026년 5월~2026년 6월

수행 유형 : 전공 과제 개인 프로젝트

[GitHub에서 프로젝트 코드 보기 →](https://github.com/dohyn38/school_member-management)

### 활동 목적

C++ 수업에서 배운 클래스와 상속을 실제 프로그램에 적용하기 위해 학교 구성원 관리 프로그램을 제작했습니다. 학교와 교수, 학부생, 대학원생, 졸업생의 정보를 파일에서 읽어 객체로 저장하고, 각 구성원의 정보를 정해진 형식으로 출력했습니다.

이번 프로젝트에서는 구성원마다 공통으로 필요한 정보와 서로 다른 정보를 구분하는 데 중점을 두었습니다. 이름과 ID는 공통으로 관리하고, 교수의 직급이나 학생의 학기처럼 유형에 따라 달라지는 정보는 각 클래스에 나누어 담았습니다.

## 3 본인 역할

전공 과제로 1인 프로젝트를 진행하였습니다.

과제에서 제공한 클래스 구조와 입력 형식을 바탕으로 학교 구성원 정보를 처리하는 기능을 구현했습니다. School에서는 구성원의 등록과 조회를 담당하도록 했고, SchoolMember와 파생 클래스에서는 공통 정보와 유형별 출력을 나누어 처리했습니다.

main.cpp에서는 학교, 교수, 학생 정보를 차례대로 읽어 알맞은 객체를 생성하도록 구성했습니다. 담당 학생 ID를 이름으로 바꾸어 출력하는 부분과 GPA를 소수점 한 자리로 표시하는 부분도 함께 구현했습니다.

프로그램을 작성하는 과정에서는 AI의 도움을 받아 코드 구조와 설명을 검토하였고, 실제 컴파일과 실행으로 확인한 내용을 반영했습니다. 구현 내용을 설명할 때는 코드에 있는 기능과 실행 결과를 기준으로 정리했습니다.

## 4 수행 과정과 선택 이유

### 클래스별 역할 구분

먼저 학교 전체의 정보와 개별 구성원의 정보를 구분했습니다. School에는 학교명, 설립 연도, 총장 ID와 전체 구성원 목록을 두었습니다. SchoolMember에는 이름, ID, 소속 학교를 저장하고, 구성원마다 다른 출력은 파생 클래스에서 처리했습니다.

Professor는 직급과 담당 학생 목록을 갖도록 했습니다. Student는 GPA를 공통으로 관리하고, UndergraduateStudent는 학기, GraduateStudent는 학위 과정, Alumni는 졸업 연도를 추가로 저장했습니다. 이렇게 나누어 같은 정보를 여러 클래스에 반복해서 작성하지 않도록 했습니다.

| 클래스 | 담당 기능 |
| --- | --- |
| School | 학교 정보 저장, 구성원 등록과 조회, 전체 출력, 등록된 객체 해제를 담당했습니다. |
| SchoolMember | 이름, ID, 소속 학교를 관리하고 공통 출력 인터페이스를 정의했습니다. |
| Professor | 직급과 담당 학생 ID 목록을 저장하고 교수 정보를 출력했습니다. |
| Student | 학생의 공통 정보인 GPA를 관리했습니다. |
| UndergraduateStudent | 학부생의 학기 정보를 저장하고 출력했습니다. |
| GraduateStudent | 대학원생의 학위 과정 정보를 저장하고 출력했습니다. |
| Alumni | 졸업생의 졸업 연도를 저장하고 출력했습니다. |

### 파일에서 읽은 정보를 객체로 변환

입력 파일은 학교, 교수, 학생 구역으로 나누어 읽었습니다. 각 줄의 정보는 쉼표로 구분되므로 split() 함수에서 쉼표의 위치를 찾아 문자열을 나누었습니다. 설립 연도와 학기, 졸업 연도는 정수로 바꾸었고, GPA는 실수로 바꾸었습니다.

학생 정보의 첫 번째 값이 U이면 학부생, G이면 대학원생, A이면 졸업생 객체를 생성했습니다. 생성한 객체는 School에 등록해 한 곳에서 관리했습니다.

### ID를 기준으로 구성원 연결

교수 정보에는 담당 학생의 이름 대신 ID가 들어 있습니다. 이 ID를 vector에 저장하고, 모든 구성원을 등록한 뒤 출력할 때 School의 조회 함수로 학생 객체를 찾았습니다. 따라서 교수 정보를 먼저 읽어도 학생의 이름을 출력할 수 있었습니다.

전체 구성원은 std::map에 ID와 객체 포인터를 묶어 저장했습니다. ID로 바로 조회할 수 있고, 서로 다른 구성원도 SchoolMember 포인터로 함께 관리할 수 있어 이 구조를 사용했습니다. 전체 출력은 map의 ID 정렬 순서에 따라 이루어집니다.

### 출력과 메모리 해제

School::print()에서는 학교 기본 정보를 출력한 뒤 각 구성원의 print()를 호출했습니다. 같은 함수를 호출하더라도 교수는 직급과 담당 학생을, 학생은 자신의 유형에 맞는 정보를 출력하도록 가상 함수를 사용했습니다.

GPA는 ostringstream과 fixed, setprecision(1)을 사용해 소수점 한 자리로 맞추었습니다. 담당 학생이 없는 교수는 No Student로 표시했습니다. 조회할 수 없는 ID는 이름 대신 해당 ID를 출력하도록 처리했습니다.

객체를 new로 생성했기 때문에 해제하는 위치도 정했습니다. School의 소멸자에서 등록된 구성원을 delete하도록 했고, 기반 클래스에는 가상 소멸자를 두었습니다. 마지막에 School을 삭제하면 등록된 구성원도 함께 정리됩니다.

## 6 회고

### 배운 점

이번 과제에서는 수업에서 따로 배웠던 상속, 가상 함수, 파일 입출력과 컨테이너를 하나의 프로그램에서 사용했습니다. 처음부터 모든 정보를 한 클래스에 넣는 대신, 공통 정보와 유형별 정보를 나누면서 각 클래스가 맡는 역할을 정리할 수 있었습니다.

특히 기반 클래스 포인터로 서로 다른 구성원을 관리하고 print()를 호출하는 과정에서 다형성이 실제로 어떻게 사용되는지 이해했습니다. 교수의 담당 학생을 ID로 저장했다가 출력 시 이름을 조회하는 구조를 통해 객체 사이의 관계를 연결하는 방법도 익혔습니다.

또한 소스 코드를 작성하는 것과 실제 결과를 확인하는 것은 별개의 과정이라는 점을 느꼈습니다. 예시 입력으로 실행한 결과를 비교하면서 학교 정보뿐 아니라 담당 학생이 없는 경우와 학생 유형별 추가 정보까지 확인했습니다.

### 한계와 개선 방향

과제에서 요구한 기본 기능의 구현과 예시 입력에 대한 실행 확인은 마쳤습니다. 다만 현재 코드는 정해진 입력 형식을 전제로 하므로 파일이 없거나 숫자가 잘못 입력된 경우의 처리가 충분하지 않습니다. 동일한 ID를 다시 등록하면 기존 포인터를 덮어쓰는 문제도 남아 있습니다.

프로그램을 확장한다면 파일 열기와 필드 개수 검사, 숫자 변환 예외 처리, 중복 ID 검사를 우선 보완하는 작업이 필요할 것 같습니다.

이번 결과물은 정상 형식의 입력을 처리하는 과제 범위에서 완성했습니다. 그 과정에서 기능 구현뿐 아니라 출력 확인과 코드의 한계를 함께 정리하는 경험을 쌓았습니다.
