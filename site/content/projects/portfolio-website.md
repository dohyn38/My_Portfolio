## 1 활동 개요

**수행 시기:** 2026년 10월 ~ 2026년 11월

**수행 유형:** 전공 과제 개인 프로젝트

[GitHub에서 프로젝트 코드 보기 →](https://github.com/dohyn38/My_Portfolio)

### 활동 목적

자기소개와 관심 분야, 학습 계획, 프로젝트 경험을 정리할 수 있는 포트폴리오 웹사이트를 제작했습니다. 프로젝트의 결과만 나열하기보다는 사용한 기술과 수행 과정, 본인 역할과 결과를 함께 볼 수 있도록 구성했습니다.

Hugo와 PaperMod 기반 테마를 사용해 기본 구조를 마련하고, Codex의 도움을 받아 HTML과 CSS를 수정하면서 원하는 화면으로 바꾸었습니다. 홈에서는 프로필과 프로젝트를 먼저 보여주고, 자세한 소개와 학습 계획은 About Me 페이지에서 확인하도록 분리했습니다.

## 2 사용 기술과 적용

| 기술 및 도구 | 적용 내용 |
| --- | --- |
| Hugo | 레이아웃과 Markdown 콘텐츠를 결합해 정적 웹페이지를 생성했습니다. 홈과 About Me에는 전용 레이아웃을 사용하고, 활동 보고서는 Markdown으로 작성해 프로젝트 상세 페이지에 표시했습니다. |
| HTML | 프로필, 메뉴, 프로젝트 카드와 목차의 구조를 구성했습니다. 구역마다 ID를 부여해 링크를 누르면 해당 위치로 이동하도록 연결했습니다. |
| CSS | 다크·라이트 모드의 색상, 그라데이션, 글자 크기와 간격을 조정했습니다. 화면 크기에 따라 카드와 목차의 배치가 바뀌도록 설정하고, 제목과 구분선으로 긴 보고서의 내용을 나누었습니다. |
| JavaScript | 스크롤 위치에 따라 현재 보고 있는 목차 항목이 강조되도록 구현했습니다. 한글로 된 제목의 주소를 처리하고, 긴 목차에서는 현재 항목이 목차 카드 안에 보이도록 조정했습니다. |
| Git과 GitHub | 브랜치별로 작업을 나누고 변경 사항을 커밋으로 기록했습니다. 사이트 제작 코드와 활동 프로젝트의 코드를 각각의 저장소로 관리하고, 사이트에서 해당 저장소로 이동할 수 있도록 연결했습니다. |
| GitHub Actions와 GitHub Pages | 코드를 빌드하고 사이트를 배포하는 워크플로를 설정했습니다. 저장소 이름이 포함된 사이트 주소에 맞춰 경로를 구성했습니다. |
| Codex | 코드 작성과 오류 원인 분석, 수정안 제안과 보고서 정리에 활용했습니다. 제안된 내용을 적용한 뒤 화면과 동작을 확인하며 수정 방향을 결정했습니다. |

## 3 본인 역할

전공 과제로 1인 프로젝트를 진행하였습니다. 사이트의 전체 구성과 디자인 방향을 정하고, 자기소개와 관심 분야, 학습 계획, 역량 및 프로젝트 내용을 작성했습니다. 페이지를 어디에서 나눌지, 홈에서 어떤 정보를 먼저 보여줄지 결정하며 구조를 수정했습니다.

기존 테마를 그대로 사용하는 데서 그치지 않고 프로필 배치, 상단 메뉴, About Me 구성, 프로젝트 카드와 상세 보고서 화면을 조정했습니다. 로컬 미리보기에서 수정한 내용을 확인하고, 글과 카드의 간격이나 목차 위치처럼 실제로 읽을 때 불편한 부분을 다시 수정했습니다.

코드 작성과 오류 원인 분석에는 OpenAI의 Codex를 사용했습니다. 제안받은 수정 내용을 적용한 뒤 화면과 동작을 확인하고, 원하는 디자인과 다르면 배치와 표현을 다시 조정했습니다. 본문 내용과 프로젝트 설명도 실제 학습 경험과 수행한 작업에 맞게 검토했습니다.

## 4 수행 과정과 선택 이유

### 홈과 소개 페이지 분리

처음에는 소개와 학습 계획, 활동 내용을 홈에 함께 배치했습니다. 이후 홈에서 프로젝트를 먼저 확인할 수 있도록 구성하고, 소개와 관심 분야, 학습 계획은 About Me 페이지로 옮겼습니다. 상단 메뉴도 Projects와 About Me로 정리했습니다.

홈에는 프로필 사진과 이름, 소속, GitHub 아이콘과 소개 문구를 배치했습니다. 그 아래에는 프로젝트 카드를 두고 상세 보고서와 코드 저장소로 이동하도록 연결했습니다. 홈은 전체 내용을 살펴보는 역할을, 개별 페이지는 자세한 내용을 읽는 역할을 하도록 구분했습니다.

### About Me 구성

About Me는 소개, 관심 분야, 학습 목표 및 실행 계획, 역량 및 사용 기술의 네 구역으로 나누었습니다. 관심 분야에는 네트워크와 보안에 대한 흥미를, 학습 계획에는 데이터통신과 소켓 프로그램 실습 방향을 작성했습니다.

역량 영역에서는 전공에서 학습한 프로그래밍 언어와 이번 프로젝트에서 활용한 기술을 구분했습니다. 기술 이름만 나열하지 않고 실제로 학습하거나 사용한 내용을 함께 적어 경험의 범위를 보여주었습니다.

### 색상과 화면 배치 조정

기본 모드는 다크 모드로 설정했습니다. 배경과 카드, 글자색을 함께 조정해 일부 요소만 색이 바뀌는 문제를 줄였고, 밝은 모드에서도 내용을 읽을 수 있도록 색상을 따로 설정했습니다. 홈과 소개 페이지, 프로젝트 상세 화면에는 그라데이션을 적용해 전체 분위기를 맞추었습니다.

소개 본문은 카드가 반복되는 구성을 줄이고 문단 중심으로 정리했습니다. 역량은 표로 표시하고, 프로젝트 보고서에서는 큰 제목에 강조색과 선을 적용해 정보의 구분이 보이도록 했습니다. 좁은 화면에서는 오른쪽 목차를 본문 위로 옮겨 글과 겹치지 않도록 구성했습니다.

### 프로젝트 상세 페이지 구성

활동 보고서는 활동 개요, 사용 기술과 적용, 본인 역할, 수행 과정과 선택 이유, 실행 결과물, 회고의 순서로 구성했습니다. 활동 1에는 C++ 학교 구성원 관리 프로그램의 보고서와 실행 결과 이미지를 적용했습니다.

상세 페이지 맨 위에는 기간과 사용 기술, 코드 링크를 담은 작은 요약 카드를 넣었습니다. 활동 개요에서도 코드 저장소에 바로 접근할 수 있도록 링크를 추가했습니다. 홈 카드와 상세 페이지의 코드 링크는 같은 프로젝트 저장소를 가리키도록 연결했습니다.

### 오른쪽 목차와 현재 위치 표시

긴 보고서에서 원하는 항목을 빠르게 찾을 수 있도록 오른쪽에 목차 카드를 배치했습니다. 목차를 누르면 본문의 해당 제목으로 이동하고, 스크롤하면 현재 읽고 있는 항목에 주황색 표시가 나타나도록 했습니다.

### 아이콘과 메뉴 오류 수정

GitHub 아이콘을 추가했을 때 아이콘이 의도보다 크게 표시되는 문제가 있었습니다. SVG의 크기를 명시하고 관련 스타일을 조정해 프로필 옆에 작은 아이콘으로 배치했습니다.

상단 메뉴가 잘리거나 좁은 화면에서 배치가 흐트러지는 부분도 수정했습니다. 메뉴의 줄바꿈과 너비를 조정하고, 화면 크기에 따라 배치가 달라지도록 공통 헤더 스타일을 보완했습니다.

### 버전 관리와 배포 구성

콘텐츠, 디자인, 메뉴와 실험 작업을 구분할 수 있도록 브랜치를 사용했습니다. 작업 내용을 커밋으로 남기면서 이전 변경 사항을 확인할 수 있도록 관리했습니다. 로컬 빌드 결과는 다시 생성할 수 있으므로 site/public을 Git 추적 대상에서 제외했습니다.

GitHub Actions에는 Hugo 빌드와 GitHub Pages 배포 단계를 구성했습니다. 브랜치의 배포가 환경 보호 규칙에 막히는 경우에는 워크플로의 실행 조건과 배포 환경의 허용 조건을 함께 확인했습니다. 배포 설정과 사이트의 경로 설정이 모두 맞아야 공개 주소에서 정상적으로 연결된다는 점을 확인했습니다.

## 5 구현 결과물

### 구현 결과

홈에서는 프로필과 소개 문구, 프로젝트 목록을 확인할 수 있도록 구성했습니다. About Me에서는 소개와 관심 분야, 학습 계획, 역량을 확인할 수 있으며, 프로젝트 카드에서는 상세 보고서와 코드 저장소로 이동할 수 있도록 연결했습니다.

활동 1 상세 페이지에는 학교 구성원 관리 프로그램의 보고서, 기술 및 클래스 설명 표, 실행 결과 이미지와 GitHub 링크를 적용했습니다. 오른쪽 목차에는 큰 항목과 세부 항목을 함께 표시하고 현재 읽는 위치를 강조하도록 구성했습니다.

### 주요 수정 파일

- site/layouts/home.html: 홈의 프로필과 프로젝트 카드
- site/layouts/about.html: 소개와 관심 분야, 학습 계획, 역량
- site/layouts/projects/single.html: 프로젝트 요약 카드, 본문과 오른쪽 목차
- site/content/projects/portfolio.md: 활동 1 보고서 본문
- site/assets/css/extended/custom.css: 색상, 간격, 반응형 배치와 목차 스타일
- site/assets/js/about-toc.js: 현재 목차 항목 추적
- site/pages.json: 사이트 주소, 상단 메뉴, 기본 테마와 파비콘 설정

## 6 회고

### 배운 점

이번 프로젝트에서는 글을 작성하는 일과 그 글을 읽기 좋은 화면으로 구성하는 일이 서로 연결되어 있다는 점을 느꼈습니다. 내용을 한 페이지에 모으는 것보다 홈과 소개, 활동 보고서의 역할을 나누었을 때 정보를 찾기 쉬웠습니다.

HTML은 구조를 정하고, CSS는 배치와 표현을 조정하며, JavaScript는 스크롤에 반응하는 기능을 담당한다는 점을 실제 수정 과정에서 익혔습니다. Hugo에서는 콘텐츠와 레이아웃이 분리되어 있어 본문을 수정하는 위치와 디자인을 수정하는 위치도 구분해야 했습니다.

화면에 보이는 문제의 원인을 찾는 경험도 쌓았습니다. 아이콘 크기 문제에서는 SVG와 CSS의 적용 범위를 확인했고, 목차 문제에서는 화면 배치가 아니라 한글 주소와 ID를 처리하는 방식이 원인이었습니다. 원하는 모양으로 바꾸는 것뿐 아니라 수정 후 연결과 동작을 다시 확인하는 과정이 필요했습니다.

### 한계와 개선 방향

현재 사이트에는 학교 구성원 관리 프로그램과 포트폴리오 웹사이트 제작 활동을 각각의 상세 페이지로 정리했습니다. 추가 프로젝트도 같은 형식으로 정리하면 사이트 전체의 구성을 일관되게 유지할 수 있습니다.

기능 검증은 로컬 빌드와 링크 및 목차 처리 확인을 중심으로 진행했습니다. 최종 공개 버전에서는 최신 커밋과 배포 결과를 연결해 확인하고, 실제 기기의 화면과 키보드 조작, 브라우저 확대 상태도 다시 점검할 필요가 있습니다.

전체적인 디자인과 탐색 구조를 마련한 뒤에는 새로운 기능을 계속 추가하기보다 실제 활동 내용과 결과 자료를 충실하게 채우는 것이 중요하다고 생각합니다. 앞으로도 프로젝트마다 수행 과정과 선택 이유, 결과를 같은 기준으로 정리해 포트폴리오를 관리하겠습니다.
